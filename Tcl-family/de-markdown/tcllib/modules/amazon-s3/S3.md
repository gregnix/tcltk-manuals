# BESCHREIBUNG

Dieses Paket ermöglicht den Zugriff auf den Webdienst „Simple Storage Solution“ von Amazon.

Zusammenfassend lässt sich sagen, dass Amazon Simple Storage Solution einen kostenpflichtigen Webdienst bereitstellt, der die Online-Speicherung beliebiger Daten als „Ressourcen“ in „Buckets“ ermöglicht. Weitere Informationen zu diesem System finden Sie unter *http://www.amazonaws.com/*. Der Zugriff auf den Dienst erfolgt über HTTP (SOAP oder REST). Ein Großteil dieser Dokumentation ist für Sie kaum nachvollziehbar, wenn Sie mit den Begriffen und Funktionen des Amazon S3-Dienstes nicht vertraut sind.

Dieses Paket stellt Dienste zum Lesen und Schreiben der Datenelemente über die REST-Schnittstelle bereit. Zudem bietet es einige übergeordnete Operationen. Weitere Pakete derselben Distribution bieten noch mehr Funktionen.

# FEHLERMELDUNG

Die Fehlermeldung dieses Pakets nutzt \$errorCode, um detailliertere Informationen zum Vorfall zu liefern, anstatt lediglich einen Fehler auszugeben. Jeder vom S3-Paket abgefangene Fehler (und es wird versucht, alle abzufangen) kehrt mit einem \$errorCode zurück, bei dem es sich um eine Liste mit mindestens drei Elementen handelt. In allen Fällen lautet das erste Element „S3“. Das zweite Element nimmt einen von sechs Werten an, wobei dieses Element den Wert des dritten und der nachfolgenden Elemente bestimmt. S3::REST löst keinen Fehler aus, sondern gibt ein Dictionary zurück, in dem die Schlüssel „error“, „errorInfo“ und „errorCode“ gesetzt sind. Dies ermöglicht eine zuverlässige Nutzung im Hintergrund. Die möglichen zweiten Elemente sind folgende:

**usage**
: Das Paket wurde falsch verwendet. Beispielsweise wurde ein Befehl aufgerufen, der eine Konfiguration der Bibliothek erfordert, bevor diese konfiguriert wurde, oder es wurde eine ungültige Kombination von Optionen angegeben. Das dritte Element von \$errorCode enthält den Namen des Parameters, der falsch war. Das vierte Element enthält in der Regel die Argumente, die tatsächlich an die auslösende Prozedur übergeben wurden, es sei denn, der Verwendungsfehler beschränkt sich nicht auf eine einzelne Prozedur.

**local**
: Auf dem lokalen System ist ein Vorfall aufgetreten, der zu einem Fehler geführt hat. Beispielsweise wurde eine Anfrage zum Hoch- oder Herunterladen einer Datei gestellt, doch die Dateiberechtigungen haben diesen Zugriff verweigert. Das dritte Element von \$errorCode ist das ursprüngliche \$errorCode.

**socket**
: Es ist ein Problem mit dem Socket aufgetreten. Dieser wurde vorzeitig geschlossen, oder es wurde ein anderer Fehler bei der Kommunikation mit Amazon festgestellt. Das dritte Element von \$errorCode ist das ursprüngliche \$errorCode, oder manchmal die Meldung von fcopy, oder …?

**remote**
: Der Amazon Web Service hat im HTTP-Header einen Fehlercode außerhalb des 2xx-Bereichs zurückgegeben. Mit anderen Worten: Alles verlief wie dokumentiert, außer dass in diesem speziellen Fall dokumentiert war, dass es nicht funktionieren würde. Das dritte Element ist das von **::S3::REST** zurückgegebene Dictionary. Hinweis: S3::REST selbst löst diesen Fehler niemals aus, sondern gibt lediglich das Dictionary zurück. Die meisten übergeordneten Befehle lösen aus Gründen der Benutzerfreundlichkeit einen Fehler aus, sofern nicht durch ein Argument angegeben wird, dass dies nicht geschehen soll. Wenn etwas als „löst keinen S3-Remote-Fehler aus“ dokumentiert ist, bedeutet dies, dass ein Statuswert zurückgegeben wird, anstatt einen Fehler auszulösen, falls Amazon einen HTTP-Statuscode außerhalb des 2xx-Bereichs zurückgibt.

**notyet**
: Der Benutzer hat sich an die Dokumentation gehalten, doch der Autor ist noch nicht dazu gekommen, diese Funktion zu implementieren. (Derzeit fallen lediglich die TLS-Unterstützung und erweiterte Berechtigungen in diese Kategorie, ebenso wie der Befehl S3::Acl.)

**xml**
: Der Dienst hat ungültiges XML oder XML mit einem unerwarteten Schema zurückgegeben. Bei übergeordneten Befehlen, die Dienst-XML als Eingabe zum Parsen akzeptieren, kann dieser Fehler ebenfalls ausgelöst werden.


# BEFEHLE

Dieses Paket bietet mehrere unterschiedliche Komplexitätsstufen.

**•**
: Die unterste Ebene nimmt lediglich die an den Dienst zu übermittelnden Argumente entgegen, sendet diese, ruft das Ergebnis ab und stellt es dem Aufrufer zur Verfügung. *Hinweis:* Diese Ebene ermöglicht sowohl synchrone als auch ereignisgesteuerte Verarbeitung. Sie ist abhängig von den Paketen MD5, SHA1 und base64 aus Tcllib (verfügbar unter *http://core.tcl.tk/tcllib/*). Hinweis: **S3::Configure** ist erforderlich, damit **S3::REST** aufgrund des Authentifizierungsteils funktioniert; daher haben wir dies in die „unterste Ebene“ integriert.

**•**
: Die nächste Ebene wertet die Ergebnisse der Aufrufe aus und ermöglicht so Funktionen wie das Hochladen nur geänderter Dateien, die Synchronisierung von Verzeichnissen und Ähnliches.  Diese Ebene ist sowohl vom Paket „**TclXML**“ als auch vom enthaltenen Paket „**xsxp**“ abhängig. Diese Pakete werden mit package require geladen, wenn diese komplexeren Routinen aufgerufen werden, sodass nichts fehlschlägt, wenn sie nicht korrekt installiert sind.

**•**
: Ebenfalls enthalten ist ein separates Programm, das die Bibliothek nutzt. Es enthält Code zum Parsen von \$argv0 und \$argv über die Befehlszeile, wodurch der Aufruf als tclkit usw. möglich ist. (Noch nicht implementiert.)

**•**
: Ein weiteres eigenständiges Programm bietet eine grafische Benutzeroberfläche, die Funktionen zum Ziehen und Ablegen sowie ähnliche Funktionen ermöglicht. (Noch nicht implementiert.)

**•**
: Auf diesem Paket basiert auch das Programm „OddJob“. Es handelt sich um ein eigenständiges Programm, das die Verteilung von Rechenaufgaben über den Webdienst „Elastic Compute Cloud“ von Amazon ermöglicht. Das Ziel besteht darin, zumindest die untersten Schichten in reinem Tcl zu implementieren, wobei ausschließlich Komponenten aus allgemein verfügbaren Quellen, wie beispielsweise Tcllib, verwendet werden sollen.


# BEFEHLE AUF NIEDRIGER EBENE

Für diese Befehle sind keine weiteren Pakete erforderlich, die nicht oben aufgeführt sind. Sie kommunizieren direkt mit dem Dienst oder sind Hilfs- bzw. Konfigurationsroutinen. Beachten Sie, dass das Paket „xsxp“ zur Unterstützung dieses Pakets entwickelt wurde; es sollte daher überall dort verfügbar sein, wo Sie dieses Paket bezogen haben.

**S3::Configure** ?**-reset** *boolean*? ?**-retries** *integer*? ?**-accesskeyid** *idstring*? ?**-secretaccesskey** *idstring*? ?**-service-access-point** *FQDN*? ?**-use-tls** *boolean*? ?**-default-compare** *always|never|exists|missing|newer|date|checksum|different*? ?**-default-separator** *string*? ?**-default-acl** *private|public-read|public-read-write|authenticated-read|keep|calc*? ?**-default-bucket** *bucketname*?
: Es gibt einen Befehl für die Konfiguration, nämlich **S3::Configure**. Wird er ohne Argumente aufgerufen, gibt er ein Dictionary mit Schlüssel-Wert-Paaren zurück, in dem alle aktuellen Einstellungen aufgeführt sind. Wird er mit einem Argument aufgerufen, gibt er den Wert dieses einzelnen Arguments zurück.  Wenn der Befehl mit zwei oder mehr Argumenten aufgerufen wird, müssen diese paarweise übergeben werden, und die Änderungen werden der Reihe nach übernommen. Pro Interpreter gibt es nur einen Satz an Informationen zur Konfiguration. Folgende Optionen werden akzeptiert:


**-reset** *boolean*
: Standardmäßig false. Wenn der Wert true ist, werden alle bisherigen Änderungen sowie alle Änderungen, die im Rahmen desselben Aufrufs vor der Option reset vorgenommen wurden, auf die Standardwerte zurückgesetzt.

**-retries** *integer*
: Der Standardwert beträgt 3. Wenn Amazon einen 500-Fehler zurückgibt, wird nach einer exponentiellen Backoff-Verzögerung so oft ein erneuter Versuch unternommen, bevor schließlich der 500-Fehler ausgelöst wird. Dies gilt für jeden Aufruf von **S3::REST** durch übergeordnete Befehle, jedoch nicht für **S3::REST** selbst. Das heißt, **S3::REST** gibt stets den HTTP-Status 500 zurück, wenn dieser empfangen wird. Funktionen wie **S3::Put** wiederholen den PUT-Aufruf und wiederholen zudem die GET- und HEAD-Aufrufe, die zum Vergleich der Inhalte verwendet werden. Wenn Sie diesen Wert auf 0 setzen, werden Wiederholungsversuche und die damit verbundenen Verzögerungen verhindert. Darüber hinaus werden Socket-Fehler (d. h. Fehler, deren „errorCode“ mit „S3 socket“ beginnt) nach einer Wartezeit ebenfalls erneut versucht.

**-accesskeyid** *idstring*
: ...siehe nächstes...

**-secretaccesskey** *idstring*
: Beide sind standardmäßig auf eine leere Zeichenfolge gesetzt. Diese müssen vor der Ausführung von Aufrufen festgelegt werden. Dies ist Ihre S3-ID. Sobald ein Konto registriert ist, wird *http://www.amazonaws.com/* aufgerufen, eine Anmeldung durchgeführt, die Schaltfläche „Your Web Services Account“ gewählt, „AWS Access Identifiers“ ausgewählt, und die Zugriffsschlüssel-ID sowie die geheimen Zugriffsschlüssel werden angezeigt. Alle **S3::REST**-Aufrufe werden authentifiziert. Die Schuld für die unglückliche Namenswahl liegt bei Amazon.

**-service-access-point** *FQDN*
: Standardmäßig ist „s3.amazonaws.com“ eingestellt. Dies ist der vollqualifizierte Name des Servers, der bei Aufrufen von **S3::REST** kontaktiert werden soll. Sie sollten diese Einstellung wahrscheinlich nie ändern müssen, es sei denn, jemand anderes implementiert einen kompatiblen Dienst oder Sie möchten Tests durchführen, indem Sie die Bibliothek auf Ihren eigenen Dienst verweisen.

**-slop-seconds** *integer*
: Wenn Datumsangaben zwischen Amazon und dem lokalen Rechner verglichen werden, werden zwei Datumsangaben, die innerhalb dieser Anzahl von Sekunden voneinander liegen, als identisch betrachtet. Dies ist nützlich für die Korrektur von Uhrenabweichungen, die Berücksichtigung von Verarbeitungsverzögerungen und Ähnliches.

**-use-tls** *boolean*
: Standardwert ist „false“. Diese Funktion ist noch nicht implementiert. Wenn „true“ aktiviert ist, baut **S3::REST** eine TLS-Verbindung zu Amazon auf. Wenn „false“ aktiviert ist, werden unverschlüsselte Verbindungen verwendet.

**-bucket-prefix** *string*
: Die Standardeinstellung lautet „TclS3“. Diese Zeichenfolge wird von **S3::SuggestBucketName** verwendet, wenn diesem Befehl eine leere Zeichenfolge als Argument übergeben wird. Sie dient dazu, verschiedene Anwendungen zu unterscheiden, die den Amazon-Dienst nutzen. Ihre Anwendung sollte diesen Wert stets festlegen, um zu verhindern, dass es zu Konflikten mit den Buckets anderer Nutzer von Amazon S3 oder mit anderen Buckets desselben Nutzers kommt.

**-default-compare** *always|never|exists|missing|newer|date|checksum|different*
: Die Standardeinstellung lautet „always“. Wenn für -compare kein Wert in **S3::Put**, **S3::Get** oder **S3::Delete** festgelegt wird, wird dieser Vergleich herangezogen. Eine Beschreibung der Bedeutung steht in den jeweiligen Befehlen.

**-default-separator** *string*
: Standardmäßig ist „/“ eingestellt. Diese Option wird derzeit nicht verwendet. Es könnte sinnvoll sein, dies für **S3::Push** und **S3::Pull** zu verwenden, doch es wäre problematisch, wenn Ressourcen Schrägstriche in ihren Namen enthalten dürften, die keine Verzeichnisse kennzeichnen. Daher hat diese Einstellung derzeit keine Auswirkung.

**-default-acl** *private|public-read|public-read-write|authenticated-read|keep|calc*
: Standardmäßig ist dies eine leere Zeichenkette. Wenn bei **S3::Put** oder **S3::Push** kein -acl-Argument angegeben wird, wird diese Zeichenkette verwendet (als x-amz-acl-Header, sofern nicht „keep“ oder „calc“ angegeben ist). Wenn dieser ebenfalls leer ist, wird kein „x-amz-acl“-Header generiert. Dies wird von **S3::REST** *nicht* verwendet.

**-default-bucket** *bucketname*
: Wenn für **S3::GetBucket**, **S3::PutBucket**, **S3::Get**, **S3::Put**, **S3::Head**, **S3::Acl**, **S3::Delete**, **S3::Push**, **S3::Pull** oder **S3::Toss** kein Bucket angegeben wird und diese Variable keine leere Zeichenkette (und nicht lediglich „/“) ist, wird dieser Wert für den Bucket verwendet. Dies ist nützlich, wenn ein Programm eine große Anzahl von Ressourcenoperationen innerhalb eines einzelnen Buckets durchführt.


**S3::SuggestBucket** ?*name*?
: Der Befehl **S3::SuggestBucket** akzeptiert eine optionale Zeichenfolge als Präfix und gibt einen gültigen Bucket zurück, der das Argument *name* sowie die Access Key ID enthält. Dadurch wird der Name für den Eigentümer und die Anwendung eindeutig (vorausgesetzt, die Anwendung wählt ein geeignetes *name*-Argument aus). Wenn kein Name angegeben wird, wird der Name aus **S3::Configure** *-bucket-prefix* verwendet. Ist auch dieser leer (was nicht der Standard ist), wird ein Fehler ausgelöst.

**S3::REST** *dict*
: Der Befehl **S3::REST** nimmt ein Dictionary als Argument entgegen und gibt ein Dictionary zurück. Das zurückgegebene Dictionary enthält dieselben Schlüssel wie das Eingabedictionary sowie zusätzliche Schlüssel als Ergebnis. Das Vorhandensein oder Fehlen von Schlüsseln im Eingabe-Dictionary kann das Verhalten der Routine steuern.  Sie löst niemals direkt einen Fehler aus, fügt jedoch bei Bedarf die Schlüssel „error“, „errorInfo“ und „errorCode“ hinzu. Einige Schlüssel sind erforderlich, andere optional. Die Routine kann je nach Vorhandensein von **resultvar** im Dictionary entweder im blockierenden oder im nicht-blockierenden Modus ausgeführt werden. Dazu müssen die Einträge *-accesskeyid* und *-secretaccesskey* vor dem Aufruf über **S3::Configure** konfiguriert werden. Folgende Eingabeschlüssel sind möglich:


**verb** *GET|PUT|DELETE|HEAD*
: Dieses Pflichtfeld gibt das zu verwendende Verb an.

**resource** *string*
: Dieses Pflichtfeld gibt die Ressource an, auf die zugegriffen werden soll. Ein führendes „/“ wird hinzugefügt, sofern es nicht bereits vorhanden ist. Bei Bedarf wird die Angabe für Sie durch URL-Kodierung bearbeitet. Ein bereits URL-kodierter Ressourcenname ist nicht anzugeben.

?**rtype** *torrent|acl*?
: Dies deutet darauf hin, dass eine Torrent- oder ACL-Ressource manipuliert wird. Dies gehört nicht in den Schlüssel **resource**, da sonst das Trennzeichen „?“ durch URL-Kodierung verändert wird.

?**parameters** *dict*?
: Dieses optionale Dictionary enthält Parameter, die der URL für die Transaktion hinzugefügt werden. Die Schlüssel müssen in der korrekten Groß-/Kleinschreibung angegeben werden (was in der Amazon-Dokumentation verwirrend ist), und die Werte müssen gültig sein. Es kann sich um ein leeres Dictionary handeln oder es kann vollständig weggelassen werden, wenn keine Parameter gewünscht sind. Es wird keine weitere Fehlerprüfung der Parameter durchgeführt.

?**headers** *dict*?
: Dieses optionale Dictionary enthält Header, die der HTTP-Anfrage hinzugefügt werden sollen. Die Schlüssel müssen in *Kleinbuchstaben* geschrieben sein, damit die Authentifizierung funktioniert. Die Werte dürfen keine eingebetteten Zeilenumbrüche oder Wagenrückläufe enthalten. Dies ist in erster Linie für das Hinzufügen von x-amz-\*-Headern nützlich. Da die Authentifizierung von **S3::REST** berechnet wird, wird dieser Header hier nicht hinzugefügt. Da content-type einen eigenen Schlüssel erhält, wird auch dieser Header hier nicht hinzugefügt.

?**inbody** *contentstring*?
: Dieses optionale Element gibt, wenn es angegeben wird, den zu sendenden Inhalt an. Es wird mit einer binären Übertragungskodierung gesendet, wobei nur die unteren Bytes verwendet werden. zu verwenden ist \[encoding convertto utf-8\], wenn es sich bei der Zeichenkette um eine UTF-8-Zeichenkette handelt. Dies wird in einem einzigen Durchgang geschrieben. Im nicht-blockierenden Modus kann ein besonders großes **inbody** den Schreib-Socket blockieren.

?**infile** *filename*?
: Dieser optionale Parameter gibt – wenn er angegeben wird und **inbody** nicht angegeben ist – den Namen der Datei an, aus der der Hauptteil der HTTP-Nachricht zusammengestellt wird. Die Datei wird zum Lesen geöffnet und schrittweise per \[fcopy\] übertragen, sodass es im nicht-blockierenden Modus nicht zu einer Blockierung kommen sollte, selbst wenn die Datei sehr groß ist. Die Datei wird im Binärmodus übertragen, sodass die Bytes auf Ihrer Festplatte mit den Bytes in Ihrer Ressource übereinstimmen. Aufgrund von HTTP-Einschränkungen muss es möglich sein, \[file size\] für diese Datei zu verwenden, um die Größe zu Beginn der Transaktion zu ermitteln.

?**S3chan** *channel*?
: Dieser optionale Parameter gibt, sofern angegeben, den bereits geöffneten Socket an, über den die Transaktion abgewickelt werden soll. Wird er nicht angegeben, wird eine Verbindung zu dem über **S3::Configure** angegebenen Service-Zugangspunkt hergestellt, bei dem es sich in der Regel um s3.amazonaws.com handelt. Wenn dieser Parameter angegeben wird, wird der Kanal am Ende der Transaktion nicht geschlossen.

?**outchan** *channel*?
: Dieses optionale Element gibt, wenn angegeben, den bereits geöffneten Kanal an, in den der von S3 zurückgegebene Hauptteil geschrieben werden soll. Das heißt: Um eine große Ressource abzurufen, wird eine Datei geöffnet, der Übersetzungsmodus festgelegt und der Kanal als Wert des Schlüssels outchan übergeben. Die Ausgabe wird stückweise in den Kanal geschrieben, damit der Speicher nicht unnötig belegt wird. Der Kanal wird am Ende der Transaktion nicht geschlossen.

?**resultvar** *varname*?
: Dieser optionale Parameter gibt, wenn angegeben, an, dass **S3::REST** im nicht-blockierenden Modus ausgeführt werden soll. Der *varname* muss in Bezug auf Namespaces vollständig qualifiziert sein und darf nicht lokal zu einer Prozedur sein. Sofern angegeben, wird das Ergebnis des Aufrufs von **S3::REST** dieser Variable zugewiesen, sobald alle Vorgänge abgeschlossen sind; trace oder vwait zeigen an, wann dies geschehen ist. Wenn dieser Schlüssel nicht angegeben wird, gibt **S3::REST** das Ergebnis einfach zurück, und es werden innerhalb dieses Aufrufs keine Aufrufe an die Ereignisschleife ausgelöst.

?**throwsocket** *throw|return*?
: Dieser optionale Eintrag gibt, sofern vorhanden, an, dass **S3::REST** einen Fehler auslösen soll, wenn throwmode auf throw gesetzt ist und ein Socket-Fehler auftritt. Er gibt an, dass **S3::REST** den Fehlercode im zurückgegebenen Dictionary zurückgeben soll, wenn ein Socket-Fehler auftritt und dieser Parameter auf return gesetzt ist. Wenn **throwsocket** auf *return* gesetzt ist oder wenn der Aufruf nicht blockierend ist, werden ein Socket-Fehler (d. h. ein Fehler, dessen Fehlercode mit „S3 socket“ beginnt) sowie **errorInfo** und **errorCode** im Dictionary unter **error** zurückgegeben. Wenn ein Vordergrundaufruf durchgeführt wird (d. h., **resultvar** wird nicht angegeben) und diese Option nicht angegeben oder auf *throw* gesetzt ist, wird stattdessen **error** aufgerufen.


Sobald der Aufruf von **S3::REST** abgeschlossen ist, gibt das Programm ein neues Dict zurück, entweder in der *resultvar* oder als Ergebnis der Ausführung. Dieses Dict ist eine Kopie des ursprünglichen Dicts, dem die Ergebnisse als neue Schlüssel hinzugefügt wurden. Folgende neue Schlüssel sind möglich:

**error** *errorstring*
: ...siehe nächstes...

**errorInfo** *errorstring*
: ...siehe nächstes...

**errorCode** *errorstring*
: Wenn ein Fehler erkannt wird, werden diese drei Schlüssel im Ergebnis gesetzt. Beachten Sie, dass **S3::REST** einen HTTP-Rückgabecode, der nicht im 2XX-Bereich liegt, *nicht* als Fehler betrachtet. Der Wert **errorCode** wird gemäß der Beschreibung unter **FEHLERMELDUNG** formatiert. Sind diese vorhanden, sind andere hier beschriebene Schlüssel möglicherweise nicht vorhanden.

**httpstatus** *threedigits*
: Der dreistellige Code aus der HTTP-Transaktion. 2XX für einen erfolgreichen Vorgang, 5XX für einen Serverfehler usw.

**httpmessage** *text*
: Die Textangabe nach dem Statuscode. „OK“ oder „Forbidden“ oder Ähnliches.

**outbody** *contentstring*
: Wenn *outchan* nicht festgelegt wurde, enthält dieser Schlüssel einen Verweis auf den (unverschlüsselten) Inhalt des zurückgegebenen Hauptteils. Wenn Amazon einen Fehler zurückgibt (d. h. der HTTP-Status ist kein 2XX-Wert), wird die Fehlermeldung in **outbody** gespeichert oder gegebenenfalls in **outchan** geschrieben.

**outheaders** *dict*
: Dieser Schlüssel enthält ein Dictionary der von Amazon zurückgegebenen Header. Die Schlüssel sind stets in Kleinbuchstaben geschrieben. Er ist vor allem nützlich, um gegebenenfalls die „x-amz-meta-\*“-Header zu finden, obwohl auch Angaben wie „last-modified“ und „content-type“ hilfreich sind. Die Schlüssel dieses Dictionary sind stets in Kleinbuchstaben geschrieben. Sowohl Schlüssel als auch Werte werden von überflüssigen Leerzeichen bereinigt.


# BEFEHLE AUF HOHER EBENE

Die Routinen in diesem Abschnitt nutzen alle einen oder mehrere Aufrufe von **S3::REST**, um ihre Aufgaben auszuführen, und analysieren und verwalten anschließend die Daten auf praktische Weise. Sofern nicht anders angegeben, lösen alle diese Befehle Fehler aus, wie unter **FEHLERMELDUNG** beschrieben.

In allen diesen Befehlen werden alle Argumente als Name-Wert-Paare in beliebiger Reihenfolge angegeben. Alle Argumentnamen beginnen mit einem Bindestrich.

Es gibt einige Optionen, die vielen Befehlen gemeinsam sind, und diese gemeinsamen Optionen werden hier beschrieben.

**-blocking** *boolean*
: Wenn dieser Parameter angegeben und auf false gesetzt ist, erfolgen alle Aufrufe von **S3:REST** nicht-blockierend, und intern rufen diese Routinen \[vwait\] auf, um die Ergebnisse abzurufen. Mit anderen Worten: Diese Routinen geben denselben Wert zurück, führen jedoch Ereignisschleifen aus, während sie auf Amazon warten.

**-parse-xml** *xmlstring*
: Wenn dieses Argument angegeben wird, überspringt die Routine die eigentliche Kommunikation mit Amazon und verhält sich stattdessen so, als wäre die übergebene XML-Zeichenkette als Hauptteil des Aufrufs zurückgegeben worden. Da einige dieser Routinen die Rückgabe von Daten in verschiedenen Formaten ermöglichen, kann dieses Argument verwendet werden, um vorhandenes XML zu analysieren und die benötigten Informationen zu extrahieren. Es ist zudem für Tests hilfreich.

**-bucket** *bucketname*
: Nahezu jeder übergeordnete Befehl muss wissen, in welchem Bucket sich die Ressourcen befinden. Diese Option legt dies fest. (Lediglich der Befehl zum Auflisten der verfügbaren Buckets benötigt diesen Parameter nicht.) Der Wert muss nicht URL-kodiert sein, selbst wenn er Sonderzeichen oder Nicht-ASCII-Zeichen enthält. Er darf führende oder nachgestellte Leerzeichen enthalten oder auch nicht – die Befehle normalisieren den Bucket. Wird dieser Parameter nicht angegeben, wird der Wert aus **S3::Configure -default-bucket** übernommen, sofern diese Zeichenfolge nicht leer ist. Hinweis: Leerzeichen und Schrägstriche werden stets an beiden Enden entfernt und der verbleibende Teil muss einen gültigen Bucket ergeben.

**-resource** *resourcename*
: Hiermit wird die gewünschte Ressource innerhalb des Buckets festgelegt. Sie kann mit einem Schrägstrich beginnen oder auch nicht – beide Fälle werden berücksichtigt. Eine URL-Kodierung ist nicht erforderlich, selbst wenn sie Sonderzeichen oder Nicht-ASCII-Zeichen enthält.

**-compare** *always|never|exists|missing|newer|date|checksum|different*
: Wenn Befehle Ressourcen in Dateien oder Dateien in Ressourcen kopieren, kann der Aufrufer festlegen, dass der Kopiervorgang übersprungen werden soll, falls der Inhalt identisch ist. Dieses Argument legt die Bedingungen fest, unter denen die Dateien kopiert werden sollen. Wird es nicht übergeben, wird das Ergebnis von **S3::Configure -default-compare** verwendet, dessen Standardwert wiederum „always“ ist. Die verschiedenen Werte haben folgende Bedeutung:


*always*
: Die Daten werden stets kopiert. Dies ist die Standardeinstellung.

*never*
: Die Daten werden niemals kopiert. Dies ist im Wesentlichen eine leere Operation, außer in den Fällen **S3::Push** und **S3::Pull**, in denen das Flag -delete möglicherweise eine Rolle spielt.

*exists*
: Die Daten werden nur kopiert, wenn das Ziel bereits vorhanden ist.

*missing*
: Die Daten werden nur kopiert, wenn das Ziel noch nicht vorhanden ist.

*newer*
: Die Daten werden kopiert, wenn das Ziel fehlt oder wenn das Datum der Quelle um mindestens **S3::Configure -slop-seconds** Sekunden neuer ist als das Datum des Ziels. Wenn die Quelle Amazon ist, wird das Datum aus dem Last-Modified-Header entnommen. Wenn die Quelle lokal ist, wird der mtime-Zeitstempel der Datei herangezogen. Wenn die Quelldaten nicht als Datei, sondern als Zeichenfolge festgelegt sind, wird der aktuelle Zeitpunkt über \[clock seconds\] verwendet.

*date*
: Ähnlich wie *newer*, nur dass kopiert wird, wenn das Datum neuer *oder* älter ist.

*checksum*
: Die MD5-Prüfsumme der lokalen Datei oder Zeichenkette wird berechnet, bei Amazon der eTag der Ressource abgefragt und die Daten werden kopiert, falls diese voneinander abweichen. Die Daten werden ebenfalls kopiert, falls das Ziel fehlt. Hinweis: Dies kann bei großen lokalen Dateien langsam sein, sofern nicht die C-Version der MD5-Unterstützung verfügbar ist.

*different*
: Die Daten werden kopiert, wenn das Ziel nicht vorhanden ist. Wenn das Ziel vorhanden ist und ein tatsächlicher Dateiname (anstelle einer Inhaltszeichenfolge) festgelegt wurde und das Datum der Datei vom Datum der Ressource abweicht, werden die Daten kopiert. Wenn die Daten als Inhaltszeichenfolge bereitgestellt werden, wird das „Datum“ als „jetzt“ behandelt, sodass es sich wahrscheinlich immer unterscheiden wird, es sei denn, der Wert für slop-seconds ist groß. Sind die Datumsangaben identisch, werden die MD5-Prüfsummen verglichen, und die Daten werden kopiert, wenn sich die Prüfsummen unterscheiden.


Hinweis: „newer“ und „date“ berücksichtigen den Inhalt nicht, „checksum“ berücksichtigt die Datumsangaben nicht, „different“ prüft beides.

**-blocking** *boolean*

**-parse-xml** *xmlstring*

**-result-type** *REST*

**-result-type** *xml*

**-result-type** *pxml*

**-result-type** *dict*
: Es wird ein Dictionary mit interessanten Abschnitten des XML-Dokuments zurückgegeben. Das Dictionary enthält die folgenden Schlüssel:


**Owner/ID**

**Owner/DisplayName**

**Bucket/Name**
: Eine Liste mit Namen, jeweils einer pro Bucket.

**Bucket/CreationDate**

**-result-type** *names*
: Es wird eine Liste mit Bucket-Namen zurückgegeben, wobei alle anderen Informationen entfernt wurden. Dies ist der Standard-Ergebnistyp für diesen Befehl.

**-result-type** *owner*

**S3::PutBucket** ?**-bucket** *bucketname*? ?**-blocking** *boolean*? ?**-acl** *{}|private|public-read|public-read-write|authenticated-read*?
: Dieser Befehl erstellt einen Bucket, falls dieser noch nicht vorhanden ist. Bucket-Namen sind global eindeutig; daher kann es vorkommen, dass Sie von Amazon eine „Forbidden“-Fehlermeldung erhalten, auch wenn Sie den Bucket in **S3::ListAllMyBuckets** nicht sehen können. In **S3::SuggestBucket** finden Sie Möglichkeiten, dieses Risiko zu minimieren. Der Header „x-amz-acl“ stammt aus der Option **-acl** oder, wenn nicht festgelegt, aus **S3::Configure -default-acl**.

**S3::DeleteBucket** ?**-bucket** *bucketname*? ?**-blocking** *boolean*?
: Dieser Befehl löscht einen Bucket, sofern dieser leer ist und Sie über die entsprechenden Berechtigungen verfügen. Beachten Sie, dass die Liste der Buckets bei Amazon eine globale Ressource ist, die eine weitreichende Synchronisierung erfordert. Wenn Sie einen Bucket löschen, kann es einige Minuten (oder Stunden) dauern, bis Sie ihn neu erstellen können; bis dahin werden „Conflict“-Fehlermeldungen angezeigt.

**S3::GetBucket** ?**-bucket** *bucketname*? ?**-blocking** *boolean*? ?**-parse-xml** *xmlstring*? ?**-max-count** *integer*? ?**-prefix** *prefixstring*? ?**-delimiter** *delimiterstring*? ?**-result-type** *REST|xml|pxml|names|dict*?
: Hiermit wird der Inhalt eines Buckets aufgelistet. Das heißt, es wird eine Verzeichnisauflistung der Ressourcen innerhalb eines Buckets gegeben, ohne dass dabei Benutzerdaten übertragen werden.


**-bucket** *bucketname*
: Das übliche „Bucket“-Argument.

**-blocking** *boolean*
: Das übliche Blockierungsargument.

**-parse-xml** *xmlstring*
: Das Standardargument für „parse-xml“.

**-max-count** *integer*
: Wenn dieser Wert angegeben wird, entspricht er der maximalen Anzahl der Datensätze, die zurückgegeben werden. Wird kein Wert angegeben, wird der Code so lange wiederholt, bis alle Datensätze gefunden wurden. Nicht kompatibel mit -parse-xml. Hinweis: Wenn dieser Wert angegeben wird, erfolgt nur ein Aufruf von **S3::REST**. Andernfalls werden so viele Aufrufe durchgeführt, bis die Liste vollständig abgearbeitet ist, wobei die Ergebnisse im Arbeitsspeicher zwischengespeichert werden. Seien Sie daher vorsichtig, falls Sie mit sehr großen Datensätzen arbeiten.

**-prefix** *prefixstring*
: Wenn vorhanden, beschränkt dies die Auflistung auf Ressourcen mit einem bestimmten Präfix. Ein eventuell vorhandenes führendes „/“ wird entfernt.

**-delimiter** *delimiterstring*
: Wenn angegeben, legt es ein Trennzeichen für die Auflistung fest. Durch die Angabe dieses Trennzeichens werden mehrere Ressourcen zu einem Eintrag zusammengefasst, so als ob S3 Verzeichnisse unterstützen würde. Weitere Informationen finden Sie in der Amazon-Dokumentation.

**-result-type** *REST|xml|pxml|names|dict*
: Dies gibt das Format des vom Befehl zurückgegebenen Ergebnisses an.


**REST**
: Wenn *-max-count* festgelegt wird, gibt **S3::REST** das Dictionary zurück. Wenn *-max-count* nicht festgelegt ist, gibt es eine Liste aller Dictionarys zurück, die durch einen oder mehrere Aufrufe von **S3::REST** zurückgegeben wurden.

**xml**
: Wenn *-max-count* festgelegt wird, wird der von **S3::REST** zurückgegebene Hauptteil zurückgegeben. Wenn *-max-count* nicht festgelegt wird, wird eine Liste aller Hauptteile zurückgegeben, die von einem oder mehreren Aufrufen von **S3::REST** zurückgegeben wurden.

**pxml**
: Wenn *-max-count* festgelegt wird, wird der von **S3::REST** zurückgegebene Hauptteil durch **xsxp::parse** geleitet und anschließend zurückgegeben. Wenn *-max-count* nicht festgelegt ist, wird jeder der von einem oder mehreren Aufrufen von **S3::REST** zurückgegebenen Hauptteile durch **xsxp::parse** geleitet und die Liste dann zurückgegeben.

**names**
: Gibt eine Liste aller Namen zurück, die entweder in den Feldern „Contents/Key“ oder in den Feldern „CommonPrefixes/Prefix“ gefunden wurden. Wenn weder *-delimiter* noch *-max-count* festgelegt sind, gibt diese Funktion eine Liste aller Ressourcen mit dem festgelegten *-prefix* zurück.

**dict**
: Gibt ein Dictionary zurück. (Es wird immer nur ein Dictionary zurückgegeben, auch wenn *-max-count* nicht festgelegt wurde.) Das Dictionary enthält folgende Schlüssel:


**Name**
: Der Name des Buckets (aus dem letzten Aufruf von **S3::REST**).

**Prefix**
: Aus dem letzten Aufruf von **S3::REST**.

**Marker**
: Aus dem letzten Aufruf von **S3::REST**.

**MaxKeys**
: Aus dem letzten Aufruf von **S3::REST**.

**IsTruncated**
: Ausgehend vom letzten Aufruf von **S3::REST**; daher stets „false“, wenn *-max-count* nicht angegeben ist.

**NextMarker**
: Wird immer bereitgestellt, wenn „IsTruncated“ auf „true“ gesetzt ist, und berechnet, falls Amazon diesen Wert nicht bereitstellt. Kann leer sein, wenn „IsTruncated“ auf „false“ gesetzt ist.

**Key**
: Eine Liste der Namen der Ressourcen im Bucket, die den Einschränkungen *-prefix* und *-delimiter* entsprechen.

**LastModified**
: Eine Liste der Zeitangaben der Ressourcen im Bucket, in derselben Reihenfolge wie Key, in dem von Amazon zurückgegebenen Format. (Das heißt, sie wird nicht in Sekunden seit der Epoche umgewandelt.)

**ETag**
: Eine Liste von Entity-Tags (auch bekannt als MD5-Prüfsummen) in derselben Reihenfolge wie „Key“.

**Size**
: Eine Liste der Größen der Ressourcen in Byte, in derselben Reihenfolge wie „Key“.

**Owner/ID**
: Eine Liste der Eigentümer der Ressourcen im Bucket, in derselben Reihenfolge wie „Key“.

**Owner/DisplayName**
: Eine Liste der Eigentümer der Ressourcen im Bucket, in derselben Reihenfolge wie bei Key. Dabei handelt es sich um die Anzeigenamen.

**CommonPrefixes/Prefix**
: Eine Liste von Präfixen, die mehreren Entitäten gemeinsam sind. Diese ist nur vorhanden, wenn *-delimiter* angegeben wurde.


**S3::Put** ?**-bucket** *bucketname*? **-resource** *resourcename* ?**-blocking** *boolean*? ?**-file** *filename*? ?**-content** *contentstring*? ?**-acl** *private|public-read|public-read-write|authenticated-read|calc|keep*? ?**-content-type** *contenttypestring*? ?**-x-amz-meta-\*** *metadatatext*? ?**-compare** *comparemode*?
: Dieser Befehl sendet Daten zur Speicherung an eine Ressource auf den Servern von Amazon unter Verwendung des HTTP-PUT-Befehls. Er gibt den Wert 0 zurück, wenn der Modus **-compare** die Übertragung verhindert hat, den Wert 1, wenn die Übertragung erfolgreich war, oder löst einen Fehler aus, wenn die Übertragung versucht wurde, aber fehlgeschlagen ist. 5XX-Fehler des Servers und S3-Socket-Fehler werden gemäß den Einstellungen von **S3:Configure -retries** erneut versucht, bevor ein Fehler ausgelöst wird; andere Fehler lösen sofort einen Fehler aus.


**-bucket**
: Hiermit wird der Bucket festgelegt, in den die Ressource geschrieben wird. Führende und/oder abschließende Schrägstriche werden für Sie entfernt, ebenso wie Leerzeichen.

**-resource**
: Dies ist der vollständige Name der Ressource innerhalb des Buckets. Ein einzelner führender Schrägstrich wird entfernt, ein abschließender Schrägstrich jedoch nicht. Leerzeichen werden nicht entfernt.

**-blocking**
: Das Standard-Blockierungsflag.

**-file**
: Wenn dies festgelegt wird, muss der *filename* vorhanden und lesbar sein und darf keine Sonderdatei oder Verzeichnisdatei sein. \[file size\] muss für diese Datei gelten und darf sich während der gesamten Laufzeit des Aufrufs nicht ändern. Der Standard-Content-Type wird anhand des Namens und/oder des Inhalts der Datei berechnet. Die Angabe dieser Option führt zu einem Fehler, wenn gleichzeitig **-content** angegeben ist; es muss jedoch mindestens eine der Optionen **-file** oder **-content** angegeben werden. (Die Datei darf nicht vorhanden oder nicht lesbar sein, wenn **-compare** *never* festgelegt ist.)

**-content**
: Wenn dies festgelegt wird, wird der *contentstring* als Hauptteil der Ressource gesendet. Der Content-Type ist standardmäßig „application/octet-string“. Es werden nur die unteren Bytes gesendet; daher sind Nicht-ASCII-Zeichen bei Bedarf vor der Übergabe an diese Routine entsprechend zu kodieren (z. B. mit \[encoding convertto utf-8\]). Die Angabe dieser Option führt zu einem Fehler, wenn gleichzeitig **-file** angegeben ist; es muss jedoch mindestens eine der Optionen **-file** oder **-content** angegeben werden.

**-acl**
: Wenn nicht anders angegeben, ist der Standardwert „**S3::Configure -default-acl**“. Hiermit wird der „x-amz-acl“-Header bei der PUT-Operation gesetzt. Wenn der Wert *calc* angegeben wird, wird der x-amz-acl-Header auf der Grundlage der Ein- und Ausgabeberechtigungen der hochzuladenden Datei berechnet; die Angabe von *calc* und **-content** führt zu einem Fehler. Wenn der Wert *keep* angegeben wird, wird die ACL der Ressource vor dem PUT-Vorgang ausgelesen (oder der Standardwert verwendet, falls die Ressource nicht existiert) und anschließend nach dem PUT-Vorgang wieder auf den ursprünglichen Wert zurückgesetzt (sofern sie existierte). Es tritt ein Fehler auf, wenn die Ressource zwar erfolgreich geschrieben wurde, die beibehaltene ACL anschließend jedoch nicht angewendet werden kann. Dies sollte niemals vorkommen. *Hinweis:*  *calc* ist derzeit noch nicht vollständig implementiert.

**-x-amz-meta-\***
: Beginnt ein Header mit „-x-amz-meta-“, wird sein Inhalt dem PUT-Befehl hinzugefügt, um als Metadaten zusammen mit der Ressource gespeichert zu werden. Auch hier erfolgt keine Kodierung, und die Metadaten sollten keine Zeichen wie Zeilenumbrüche, Wagenrückläufe usw. enthalten. Am besten halten Sie sich an einfache ASCII-Zeichenfolgen oder passen die Bibliothek an mehreren Plätzen entsprechend an.

**-content-type**
: Dies überschreibt den von **-file** berechneten Content-Type oder legt den Content-Type für **-content** fest.

**-compare**
: Dies ist das Standardargument für den Vergleichsmodus. **S3::Put** gibt den Wert 1 zurück, wenn die Daten kopiert wurden, bzw. den Wert 0, wenn die Daten aufgrund des Vergleichsmodus übersprungen wurden, was darauf hinweist, dass sie übersprungen werden sollten.


**S3::Get** ?**-bucket** *bucketname*? **-resource** *resourcename* ?**-blocking** *boolean*? ?**-compare** *comparemode*? ?**-file** *filename*? ?**-content** *contentvarname*? ?**-timestamp** *aws|now*? ?**-headers** *headervarname*?
: Dieser Befehl ruft Daten von einer Ressource auf den S3-Servern von Amazon ab und verwendet dabei den HTTP-GET-Befehl. Er gibt den Wert 0 zurück, wenn der Modus **-compare** die Übertragung verhindert hat, den Wert 1, wenn die Übertragung erfolgreich war, oder löst einen Fehler aus, wenn die Übertragung versucht wurde, aber fehlgeschlagen ist. 5XX-Fehler des Servers und S3-Socket-Fehler werden gemäß den Einstellungen von **S3:Configure** erneut versucht, bevor ein Fehler ausgelöst wird; andere Fehler werden sofort ausgelöst. Hinweis: Die Authentifizierung erfolgt stets als der über **S3::Configure -accesskeyid** konfigurierte Benutzer. Für nicht authentifizierte GET-Anfragen dient das Tcllib-Paket http.


**-bucket**
: Hiermit wird der Bucket festgelegt, aus dem die Ressource gelesen wird. Führende und/oder abschließende Schrägstriche werden für Sie entfernt, ebenso wie Leerzeichen.

**-resource**
: Dies ist der vollständige Name der Ressource innerhalb des Buckets. Ein einzelner führender Schrägstrich wird entfernt, ein abschließender Schrägstrich jedoch nicht. Leerzeichen werden nicht entfernt.

**-blocking**
: Das Standard-Blockierungsflag.

**-file**
: Wenn dies festgelegt wird, wird der Inhalt der Ressource schrittweise in diese Datei eingelesen, ohne ihn zuvor vollständig in den Arbeitsspeicher zu laden. Das übergeordnete Verzeichnis muss bereits vorhanden sein. Wenn die Datei bereits existiert, muss sie beschreibbar sein. Wird während des Prozesses ein Fehler ausgelöst und die Datei existierte bereits, kann sie überschrieben werden. Wird während des Prozesses ein Fehler ausgelöst und die Datei existierte noch nicht, werden alle bereits geschriebenen Teile gelöscht. Die Angabe dieser Option führt zu einem Fehler, wenn gleichzeitig **-content** angegeben ist; es muss jedoch mindestens eine der Optionen **-file** oder **-content** angegeben werden.

**-timestamp**
: Dies gilt nur in Verbindung mit **-file**. Es kann als *now* oder *aws* angegeben werden. Die Standardeinstellung ist *now*. Bei *now* wird das Änderungsdatum der Datei dem System überlassen. Wenn *aws* aktiv ist, wird die Mtime der Datei so gesetzt, dass sie mit dem „Last-Modified“-Header der Ressource übereinstimmt, wodurch die beiden Werte für **-compare** *date* oder **-compare** *newer* entsprechend synchronisiert werden.

**-content**
: Wenn dies festgelegt wird, ist *contentvarname* eine Variable im Geltungsbereich des Aufrufers (nicht unbedingt global), die den Wert des Hauptteils der Ressource entgegennimmt. Es erfolgt keine Kodierung; wenn die Ressource (beispielsweise) eine UTF-8-Bytefolge darstellt, liefert \[encoding convertfrom utf-8\] eine gültige UTF-8-Zeichenkette. Wenn dies festgelegt wird, wird **-compare** ignoriert, es sei denn, es handelt sich um *never*; in diesem Fall erfolgt keine Zuweisung an *contentvarname*. Die Angabe dieses Parameters ist ein Fehler, wenn gleichzeitig **-file** angegeben ist; es muss jedoch mindestens einer der Parameter **-file** oder **-content** angegeben werden.

**-compare**
: Dies ist das Standardargument für den Vergleichsmodus. **S3::Get** gibt den Wert 1 zurück, wenn die Daten kopiert wurden, oder den Wert 0, wenn die Daten aufgrund des Vergleichsmodus übersprungen wurden, was darauf hinweist, dass sie übersprungen werden sollten.

**-headers**
: Wenn dies festgelegt wird, werden die beim Abruf erzeugten Header als Dictionary in der angegebenen Variable gespeichert. Dazu gehören Content-Type- und x-amz-meta-\*-Header sowie die üblichen HTTP-Header, die x-amz-id-Debugging-Header und so weiter. Wenn keine Datei abgerufen wird (aufgrund von **-compare** oder anderen Fehlern), erfolgt keine Zuweisung an diese Variable.


**S3::Head** ?**-bucket** *bucketname*? **-resource** *resourcename* ?**-blocking** *boolean*? ?**-dict** *dictvarname*? ?**-headers** *headersvarname*? ?**-status** *statusvarname*?
: Dieser Befehl fordert den HEAD-Befehl von der Ressource an. Er gibt zurück, ob als Ergebnis der Anfrage ein 2XX-Code zurückgegeben wurde, und löst dabei niemals einen S3-Remote-Fehler aus. Das heißt, wenn dieser Befehl den Wert 1 zurückgibt, ist die Ressource vorhanden und zugänglich. Wenn der Befehl den Wert 0 zurückgibt, ist ein Fehler aufgetreten; Einzelheiten können dem Ergebnis **-status** entnommen werden.


**-bucket**
: Hiermit wird der Bucket festgelegt, aus dem die Ressource gelesen wird. Führende und/oder abschließende Schrägstriche werden für Sie entfernt, ebenso wie Leerzeichen.

**-resource**
: Dies ist der vollständige Name der Ressource innerhalb des Buckets. Ein einzelner führender Schrägstrich wird entfernt, ein abschließender Schrägstrich jedoch nicht. Leerzeichen werden nicht entfernt.

**-blocking**
: Das Standard-Blockierungsflag.

**-dict**
: Wenn angegeben, wird das aus dem Aufruf von **S3::REST** resultierende Dictionary der angegebenen (nicht unbedingt globalen) Variablen im Geltungsbereich des Aufrufers zugewiesen.

**-headers**
: Wenn angegeben, wird das Dictionary der Header aus dem Ergebnis den angegebenen (nicht unbedingt globalen) Variablen im Geltungsbereich des Aufrufers zugewiesen.

**-status**
: Wenn eine Variable festgelegt wird, wird der angegebenen (nicht unbedingt globalen) Variable im Gültigkeitsbereich des Aufrufers eine Liste mit zwei Elementen zugewiesen. Das erste Element ist der dreistellige HTTP-Statuscode, während das zweite Element die HTTP-Meldung ist (z. B. „OK“ oder „Forbidden“).


**S3::GetAcl** ?**-blocking** *boolean*? ?**-bucket** *bucketname*? **-resource** *resourcename* ?**-result-type** *REST|xml|pxml*?
: Dieser Befehl ruft die ACL der angegebenen Ressource ab oder löst einen Fehler aus, falls diese nicht verfügbar ist.


**-blocking** *boolean*
: Die Standarddefinition finden Sie weiter oben.

**-bucket**
: Hiermit wird der Bucket festgelegt, aus dem die Ressource gelesen wird. Führende und/oder abschließende Schrägstriche werden für Sie entfernt, ebenso wie Leerzeichen.

**-resource**
: Dies ist der vollständige Name der Ressource innerhalb des Buckets. Ein einzelner führender Schrägstrich wird entfernt, ein abschließender Schrägstrich jedoch nicht. Leerzeichen werden nicht entfernt.

**-parse-xml** *xml*
: Das XML aus einem früheren GetACL-Aufruf kann übergeben werden, um in eine Dictionary-Form geparst zu werden. In diesem Fall muss -result-type den Typ „pxml“ oder „dict“ haben.

**-result-type** *REST*
: Das von **S3::REST** zurückgegebene Dictionary ist der Wert von **S3::GetAcl**. In diesem Fall löst ein HTTP-Status, der nicht der Klasse 2XX angehört, keinen Fehler aus.

**-result-type** *xml*
: Als Ergebnis wird das rohe XML des Hauptteils zurückgegeben (ohne jegliche Kodierung).

**-result-type** *pxml*
: Es gibt den von **xsxp::parse** geparsten XML-Code des Hauptteils zurück.

**-result-type** *dict*
: Diese Funktion ruft die ACL ab, wertet sie aus und gibt ein Dictionary mit zwei Elementen zurück. Das erste Element hat den Schlüssel „owner“, dessen Wert die kanonische ID des Eigentümers der Ressource ist. Das zweite Element hat den Schlüssel „acl“, dessen Wert ein Dictionary ist. Jeder Schlüssel in diesem Dictionary entspricht einer der Amazon-Berechtigungen, nämlich „READ“, „WRITE“, „READ_ACP“, „WRITE_ACP“ oder „FULL_CONTROL“.  Jeder Wert eines Schlüssels ist eine Liste kanonischer IDs oder Gruppen-URLs, die über diese Berechtigung verfügen. Die Elemente sind in der Liste nicht in einer bestimmten Reihenfolge angeordnet, und es sind nicht unbedingt alle Schlüssel vorhanden. Anzeigenamen werden nicht zurückgegeben, da sie nicht besonders nützlich sind; bei Bedarf liefert pxml diese.


**S3::PutAcl** ?**-blocking** *boolean*? ?**-bucket** *bucketname*? **-resource** *resourcename* ?**-acl** *new-acl*?
: Damit wird die ACL für die angegebene Ressource festgelegt. Die Funktion gibt das in die ACL geschriebene XML zurück oder löst einen Fehler aus, falls ein Fehler aufgetreten ist.


**-blocking** *boolean*
: Die Standarddefinition finden Sie weiter oben.

**-bucket**
: Hiermit wird der Bucket festgelegt, aus dem die Ressource gelesen wird. Führende und/oder abschließende Schrägstriche werden für Sie entfernt, ebenso wie Leerzeichen.

**-resource**
: Dies ist der vollständige Name der Ressource innerhalb des Buckets. Ein einzelner führender Schrägstrich wird entfernt, ein abschließender Schrägstrich jedoch nicht. Leerzeichen werden nicht entfernt.

**-owner**
: Wenn dieser Wert angegeben wird, wird davon ausgegangen, dass er mit dem Eigentümer der Ressource übereinstimmt. Andernfalls muss möglicherweise ein GET-Aufruf an die Ressource gesendet werden, um den Eigentümer zu ermitteln. Wenn Sie den Eigentümer bereits kennen (beispielsweise aus einem Aufruf von **S3::GetAcl**), können Sie den Wert des Schlüssels „owner“ als Wert dieser Option übergeben; dieser wird dann bei der Erstellung des XML-Dokuments verwendet.

**-acl**
: Wenn diese Option festgelegt wird, liefert sie die ACL, die der Aufrufer in die Ressource schreiben möchte. Wird sie nicht festgelegt oder ist sie leer, wird der Wert aus **S3::Configure -default-acl** übernommen. Die ACL wird mit einem PUT-Befehl in die Ressource „?acl“ geschrieben. Wenn der an diese Option übergebene Wert mit „<“ beginnt, wird er als Hauptteil interpretiert, der per PUT an die ACL-Ressource gesendet werden soll. Stimmt der Wert mit einem der Standard-Amazon-x-amz-acl-Header überein (d. h. einer vordefinierten Zugriffsrichtlinie), wird dieser Header in XML übersetzt und anschließend angewendet. Die vordefinierten Zugriffsrichtlinien lauten „private“, „public-read“, „public-read-write“ und „authenticated-read“ (in Kleinbuchstaben). Andernfalls wird davon ausgegangen, dass der Wert ein Dictionary ist, das als „acl“-Untereintrag innerhalb des von **S3::GetAcl -result-type dict** zurückgegebenen Dictionarys formatiert ist. Der entsprechende Wert wird generiert und auf die Ressource angewendet. Hinweis: Ein Wert, der „//“ enthält, wird als Gruppe angesehen, ein Wert, der „@“ enthält, wird als „AmazonCustomerByEmail“ angesehen und der Wert ansonsten als kanonische Amazon-ID angesehen. Hinweis: Sie können den Eigentümer nicht ändern; daher führt der Aufruf von „GetAcl“ für eine Ressource, die einem bestimmten Benutzer gehört, und die anschließende Anwendung über „PutAcl“ auf eine Ressource, die einem anderen Benutzer gehört, möglicherweise nicht genau zu dem Ergebnis, das Sie erwarten.


**S3::Delete** ?**-bucket** *bucketname*? **-resource** *resourcename* ?**-blocking** *boolean*? ?**-status** *statusvar*?
: Dieser Befehl löscht die angegebene Ressource aus dem angegebenen Bucket. Er gibt den Wert 1 zurück, wenn die Ressource erfolgreich gelöscht wurde, andernfalls den Wert 0. Er gibt den Wert 0 zurück, anstatt einen S3-Remote-Fehler auszulösen.


**-bucket**
: Hiermit wird der Bucket festgelegt, aus dem die Ressource gelöscht werden soll. Führende und/oder abschließende Schrägstriche werden für Sie entfernt, ebenso wie Leerzeichen.

**-resource**
: Dies ist der vollständige Name der Ressource innerhalb des Buckets. Ein einzelner führender Schrägstrich wird entfernt, ein abschließender Schrägstrich jedoch nicht. Leerzeichen werden nicht entfernt.

**-blocking**
: Das Standard-Blockierungsflag.

**-status**
: Wenn angegeben, wird die angegebene (nicht unbedingt globale) Variable im Gültigkeitsbereich des Aufrufers auf eine Liste mit zwei Elementen gesetzt. Das erste Element ist der dreistellige HTTP-Statuscode. Das zweite Element ist die HTTP-Meldung (z. B. „OK“ oder „Forbidden“). Hinweis: Das DELETE-Ergebnis von Amazon ist bei Erfolg 204; dieser Code weist darauf hin, dass der zurückgegebene Hauptteil keinen Inhalt enthält.


**S3::Push** ?**-bucket** *bucketname*? **-directory** *directoryname* ?**-prefix** *prefixstring*? ?**-compare** *comparemode*? ?**-x-amz-meta-\*** *metastring*? ?**-acl** *aclcode*? ?**-delete** *boolean*? ?**-error** *throw|break|continue*? ?**-progress** *scriptprefix*?
: Hierbei wird ein lokales Verzeichnis mit einem Remote-Bucket synchronisiert, indem die Unterschiede mithilfe von **S3::Put** übertragen werden. Zu beachten ist, dass Änderungen, die im Bucket, jedoch nicht lokal vorgenommen wurden, verloren gehen können. Daher handelt es sich hierbei nicht um eine allgemeine Primitive für die bidirektionale Synchronisation. (Siehe hierzu **S3::Sync**.) Zudem ist zu beachten, dass bei Ressourcennamen die Groß- und Kleinschreibung beachtet wird; daher kann eine Änderung der Groß-/Kleinschreibung einer Datei auf einem Windows-Rechner zu ansonsten unnötigen Übertragungen führen. Ferner werden nur reguläre Dateien berücksichtigt; Geräte, Pipes, symbolische Links und Verzeichnisse werden daher nicht kopiert.


**-bucket**
: Hiermit wird der Name des Buckets festgelegt, in den die Daten übertragen werden sollen.

**-directory**
: Hiermit wird der Name des lokalen Verzeichnisses angegeben, aus dem die Dateien entnommen werden sollen. Es muss vorhanden sein, über \[glob\] lesbar sein und so weiter. Wenn nur einige der darin enthaltenen Dateien lesbar sind, führt **S3::Push** die lesbaren Dateien mit dem Befehl „PUT“ aus und gibt in seinen Ergebnissen die Liste der Dateien zurück, die nicht geöffnet werden konnten.

**-prefix**
: Hiermit wird der Name festgelegt, der allen Ressourcen hinzugefügt wird. Das heißt, er entspricht dem Remote-Äquivalent von **-directory**. Wenn kein Präfix angegeben wird, wird das Stammverzeichnis des Buckets als Remote-Verzeichnis behandelt. Beispiele sollen dies verdeutlichen.


```
S3::Push -bucket test -directory /tmp/xyz -prefix hello/world
```

: In diesem Beispiel wird die Datei „/tmp/xyz/pdq.html“ auf den Servern von Amazon unter der Adresse „http://s3.amazonaws.com/test/hello/world/pdq.html“ gespeichert. Ebenso wird „/tmp/xyz/abc/def/Hello“ auf den Servern von Amazon als „http://s3.amazonaws.com/test/hello/world/abc/def/Hello“ gespeichert. Ohne die Option **-prefix** würde „/tmp/xyz/pdq.html“ als „http://s3.amazonaws.com/test/pdq.html“ gespeichert werden.


**-blocking**
: Dies ist die übliche Blockierungsoption.

**-compare**
: Sofern vorhanden, wird dieser Wert bei jedem Aufruf von **S3::Put** übergeben. Wenn kein Wert festgelegt ist, wird selbstverständlich **S3::Configure -default-compare** verwendet.

**-x-amz-meta-\***
: Wenn dieser Wert vorhanden ist, wird er an jeden Aufruf von **S3::Put** übergeben. Alle kopierten Dateien verfügen über dieselben Metadaten.

**-acl**
: Sofern vorhanden, wird dieser Wert bei jedem Aufruf von **S3::Put** übergeben.

**-delete**
: Der Standardwert ist „false“. Wenn der Wert „true“ ist, werden Ressourcen im Zielverzeichnis, die nicht im Quellverzeichnis vorhanden sind, mit **S3::Delete** gelöscht. Da nur reguläre Dateien berücksichtigt werden, verhindert das Vorhandensein eines symbolischen Links, einer Pipe, eines Geräts oder eines Verzeichnisses im lokalen Quellverzeichnis *nicht* das Löschen einer Remote-Ressource mit einem entsprechenden Namen.

**-error**
: Diese Option steuert das Verhalten von **S3::Push**, falls **S3::Put** einen Fehler auslöst. Hinweis: Fehler, die im lokalen Dateisystem oder beim Einlesen der Ressourcenliste im Remote-Bucket auftreten, lösen stets einen Fehler aus. Diese Option ermöglicht die Steuerung von „teilweisen“ Fehlern, bei denen einige Dateien kopiert wurden, andere jedoch nicht. **S3::Delete** wird stets abgeschlossen, wobei Fehler lediglich im Rückgabewert protokolliert werden.


**throw**
: Der Fehler wird mit demselben Fehlercode erneut ausgelöst.

**break**
: Die Verarbeitung endet, ohne dass ein Fehler ausgelöst wird; der Fehler wird im Rückgabewert erfasst, und der Befehl gibt normal zurück. Die Aufrufe von **S3::Delete** werden nicht gestartet.

**continue**
: Dies ist die Standardeinstellung. Die Verarbeitung wird fortgesetzt, ohne dass ein Fehler ausgelöst wird; der Fehler wird im Rückgabewert vermerkt, und es wird mit der nächsten zu kopierenden Datei im lokalen Verzeichnis fortgefahren.


**-progress**
: Wenn dies festgelegt wird und das angegebene Skriptpräfix nicht leer ist, wird das angegebene Skriptpräfix an verschiedenen Stellen der Verarbeitung mehrmals im Kontext des Aufrufers mit zusätzlichen Argumenten aufgerufen. Dies ermöglicht eine Fortschrittsanzeige, ohne die Verarbeitung in den Hintergrund zu verlegen.  Das angegebene Präfix wird mit zusätzlichen Argumenten aufgerufen, wobei das erste zusätzliche Argument angibt, über welchen Teil des Prozesses berichtet wird. Das Präfix wird zunächst mit *args* als erstem zusätzlichen Argument und einem Dictionary, das die normalisierten Argumente des Aufrufs von **S3::Push** darstellt, als zweitem zusätzlichen Argument aufgerufen. Anschließend wird das Präfix mit *local* als erstem zusätzlichen Argument und einer Liste der zu berücksichtigenden Dateisuffixe als zweitem Argument aufgerufen. Danach wird das Präfix mit *remote* als erstem zusätzlichen Argument und einer Liste der im Remote-Bucket vorhandenen Dateisuffixe als zweitem zusätzlichen Argument aufgerufen.  Anschließend wird für jede Datei in der lokalen Liste das Präfix mit *start* als erstem Zusatzargument und dem gemeinsamen Suffix als zweitem Zusatzargument aufgerufen.  Wenn **S3::Put** für diese Datei zurückgibt, wird das Präfix mit *copy* als erstem zusätzlichen Argument, dem gemeinsamen Suffix als zweitem zusätzlichen Argument und einem dritten Argument aufgerufen, das „copied“ ist (wenn **S3::Put** die Ressource gesendet hat), „skipped“ (falls **S3::Put** auf Grundlage von **-compare** entschieden hat, dies nicht zu tun) oder den Fehlercode, den **S3::Put** aufgrund unerwarteter Fehler ausgelöst hat (in diesem Fall ist das dritte Argument eine Liste, die mit „S3“ beginnt). Wenn alle Dateien übertragen wurden, kann das Präfix nullmal oder mehrmals mit *delete* als erstem zusätzlichen Argument und dem Suffix der zu löschenden Ressource als zweitem zusätzlichen Argument aufgerufen werden, wobei das dritte Argument entweder eine leere Zeichenkette ist (falls das Löschen erfolgreich war) oder der Fehlercode von **S3::Delete**, falls es fehlgeschlagen ist. Schließlich wird das Präfix mit *finished* als erstem zusätzlichen Argument und dem Wert als zweitem zusätzlichen Argument aufgerufen.


: Das Ergebnis dieses Befehls ist ein Dictionary. Die Schlüssel sind die Suffixe (d. h. der gemeinsame Teil des Pfads nach „**-directory**“ und „**-prefix**“), während die Werte je nach Fall entweder „copied“, „skipped“ (wenn **-compare** angibt, dass die Datei nicht kopiert werden soll) oder gegebenenfalls der von **S3::Put** ausgelöste Fehlercode. Wenn **-delete** true ist, können zudem Einträge für Suffixe mit dem Wert „deleted“ oder „notdeleted“ vorhanden sein, die angeben, ob der versuchte Vorgang **S3::Delete** erfolgreich war oder nicht. Das Rückgaberesultat enthält ein weiteres Schlüssel-Wert-Paar, dessen Schlüssel die leere Zeichenkette ist und dessen Wert ein verschachteltes Dictionary ist. Zu den Schlüsseln dieses verschachtelten Dictionaries gehören „filescopied“ (die Anzahl der erfolgreich kopierten Dateien), „bytescopied“ (die Anzahl der Datenbytes in den kopierten Dateien, ohne Header, Metadaten, usw.), „compareskipped“ (die Anzahl der Dateien, die aufgrund des Modus **-compare** nicht kopiert wurden), „errorskipped“ (die Anzahl der Dateien, die aufgrund ausgelöster Fehler nicht kopiert wurden), „filesdeleted“ (die Anzahl der Ressourcen, die gelöscht wurden, da lokal keine entsprechenden Dateien vorhanden waren, oder 0, falls **-delete** auf „false“ gesetzt ist) sowie „filesnotdeleted“ (die Anzahl der Ressourcen, deren Löschung versucht wurde, jedoch fehlschlug). Hinweis: Dies ist derzeit etwas ineffizient implementiert. Es wird zunächst die Bucket-Liste (einschließlich Zeitstempel und eTags) abgerufen, anschließend wird **S3::Put** aufgerufen, das wiederum HEAD verwendet, um die Zeitstempel und eTags erneut zu ermitteln. Eine Korrektur dieses Problems ohne API-Änderung ist für ein zukünftiges Upgrade geplant.


**S3::Pull** ?**-bucket** *bucketname*? **-directory** *directoryname* ?**-prefix** *prefixstring*? ?**-blocking** *boolean*? ?**-compare** *comparemode*? ?**-delete** *boolean*? ?**-timestamp** *aws|now*? ?**-error** *throw|break|continue*? ?**-progress** *scriptprefix*?
: Dadurch wird ein Remote-Bucket mit einem lokalen Verzeichnis synchronisiert, indem die Unterschiede mithilfe von **S3::Get** abgerufen werden. Sollten lokal Änderungen vorgenommen worden sein, die im Bucket nicht vorhanden sind, können diese Unterschiede verloren gehen. Es handelt sich hierbei nicht um einen allgemeinen Mechanismus zur bidirektionalen Synchronisation. (Siehe hierzu **S3::Sync**.) Dabei werden bei Bedarf Verzeichnisse angelegt; neue Verzeichnisse werden mit Standardberechtigungen erstellt. Beachten Sie, dass bei Ressourcennamen die Groß- und Kleinschreibung beachtet werden muss; daher kann eine Änderung der Groß-/Kleinschreibung einer Datei auf einem Windows-Rechner zu ansonsten unnötigen Übertragungen führen. Versuchen Sie außerdem, keine Daten in Ressourcen zu speichern, deren Namen mit einem Schrägstrich enden oder die Präfixe von Ressourcen sind, die ansonsten mit einem Schrägstrich beginnen würden; d. h., verwenden Sie diese Funktion nicht, wenn Sie Daten in Ressourcen speichern, deren Namen lokal Verzeichnisse sein müssen. Hinweis: Dies ist derzeit etwas ineffizient implementiert. Es ruft die Bucket-Liste (einschließlich Zeitstempel und eTags) ab und ruft dann **S3::Get** auf, das HEAD verwendet, um die Zeitstempel und eTags erneut zu ermitteln. Eine Korrektur dieses Problems ohne API-Änderung ist für ein zukünftiges Upgrade geplant.


**-bucket**
: Hiermit wird der Name des Buckets angegeben, aus dem Daten abgerufen werden sollen.

**-directory**
: Hiermit wird der Name des lokalen Verzeichnisses angegeben, in das Dateien geschrieben werden sollen. Es muss vorhanden sein, über \[glob\] lesbar sein, Schreibzugriff für die Erstellung von Dateien bieten und so weiter. Wenn nur einige der darin enthaltenen Dateien beschreibbar sind, ruft **S3::Pull** die beschreibbaren Dateien mit GET ab und gibt in seinen Ergebnissen die Liste der Dateien zurück, die nicht geöffnet werden konnten.

**-prefix**
: Das Präfix der Ressourcen, die für den Abruf in Betracht gezogen werden. Weitere Einzelheiten, Beispiele usw. finden Sie unter **S3::Push**. (Natürlich dient **S3::Pull** dem Lesen und nicht dem Schreiben, doch das Präfix wird auf ähnliche Weise behandelt.)

**-blocking**
: Dies ist die übliche Blockierungsoption.

**-compare**
: Dieser Wert wird an jeden Aufruf von **S3::Get** übergeben, sofern er angegeben ist. Ist dies nicht der Fall, wird selbstverständlich **S3::Configure -default-compare** verwendet.

**-timestamp**
: Dieser Wert wird, wenn er angegeben ist, bei jedem Aufruf von **S3::Get** übergeben.

**-delete**
: Wenn diese Option festgelegt ist und den Wert true annimmt, werden Dateien, die im **-directory** vorhanden sind, aber nicht im **-prefix** enthalten sind, gelöscht, nachdem alle Ressourcen kopiert wurden. Zudem werden leere Verzeichnisse (mit Ausnahme des obersten **-directory**) gelöscht, da Amazon S3 das Konzept eines leeren Verzeichnisses nicht kennt.

**-error**
: Eine Beschreibung dieser Option finden Sie unter **S3::Push**.

**-progress**
: Eine Beschreibung dieser Option finden Sie unter **S3::Push**. Der Unterschied besteht darin, dass lokale Verzeichnisse mit einem abschließenden Schrägstrich angegeben werden können, um zu kennzeichnen, dass es sich um Verzeichnisse handelt.


: Der Wert dieses Befehls ist ein Dictionary. Er entspricht in Form und Bedeutung der Beschreibung des Rückgabewerts von **S3::Push**. Der einzige Unterschied besteht darin, dass Verzeichnisse, deren Name mit einem abschließenden Schrägstrich endet, ebenfalls enthalten sein können, sofern sie leer sind und gelöscht werden.


**S3::Toss** ?**-bucket** *bucketname*? **-prefix** *prefixstring* ?**-blocking** *boolean*? ?**-error** *throw|break|continue*? ?**-progress** *scriptprefix*?
: Dadurch werden einige oder alle Ressourcen innerhalb eines Buckets gelöscht. Würde Amazon echte Verzeichnisse implementieren, würde dies als „rekursives Löschen“ gelten.


**-bucket**
: Der Bucket, aus dem Ressourcen gelöscht werden sollen.

**-blocking**
: Die übliche Blockierungsoption.

**-prefix**
: Das Präfix für die zu löschenden Ressourcen. Alle Ressourcen, deren Name mit dieser Zeichenfolge beginnt, werden gelöscht. Diese Angabe ist erforderlich. Um den gesamten Inhalt des Buckets zu löschen, geben Sie als Präfix eine leere Zeichenfolge an.

**-error**
: Wenn der Wert „throw“ ist, gibt **S3::Toss** alle auftretenden Fehler erneut weiter. Wenn der Wert „break“ ist, gibt **S3::Toss** nach dem ersten Fehler einen normalen Rückgabewert zurück und protokolliert diesen Fehler im Rückgabewert. Wenn der Wert „continue“ (Standardeinstellung) ist, fährt **S3::Toss** fort und listet alle Fehler im Rückgabewert auf.

**-progress**
: Wenn dies festgelegt ist und es sich nicht um eine leere Zeichenkette handelt, wird das Skriptpräfix im Kontext des Aufrufers mehrmals aufgerufen, wobei jeweils zusätzliche Argumente angehängt werden. Zunächst wird es so aufgerufen, dass das erste zusätzliche Argument *args* und das zweite die verarbeitete Liste der Argumente für **S3::Toss** ist. Anschließend wird es mit *remote* als erstem zusätzlichen Argument und der Liste der zu löschenden Suffixe im Bucket als zweitem zusätzlichen Argument aufgerufen. Anschließend wird es aufgerufen, wobei das erste zusätzliche Argument *delete* ist, das zweite zusätzliche Argument das gelöschte Suffix und das dritte zusätzliche Argument „deleted“ oder „notdeleted“, je nachdem, ob **S3::Delete** einen Fehler ausgelöst hat. Schließlich wird das Skript-Präfix mit dem ersten zusätzlichen Argument „finished“ und dem zweiten zusätzlichen Argument, dem Wert der Rückgabe, aufgerufen.


: Der Rückgabewert ist ein Dictionary. Die Schlüssel sind die Suffixe der Dateien, die **S3::Toss** zu löschen versucht hat, und deren Werte entweder die Zeichenfolge „deleted“ oder „notdeleted“ sind. Zudem gibt es ein weiteres Schlüssel-Wert-Paar, dessen Schlüssel die leere Zeichenkette ist und dessen Wert ein eingebettetes Dictionary ist. Zu den Schlüsseln dieses eingebetteten Dictionarys gehören „filesdeleted“ und „filesnotdeleted“, die jeweils ganzzahlige Werte enthalten.


# EINSCHRÄNKUNGEN

**•**
: Die MD5-Prüfung mit reinem Tcl ist langsam. Wenn Sie Dateien im Megabyte-Bereich verarbeiten, sollten Sie sicherstellen, dass eine Binärunterstützung verfügbar ist.

**•**
: Die Befehle **S3::Pull** und **S3::Push** rufen eine Verzeichnisauflistung ab, die Zeitstempel und MD5-Hashes enthält, und rufen anschließend **S3::Get** und **S3::Put** auf. Wenn ein komplexer **-compare**-Modus festgelegt wird, rufen **S3::Get** und **S3::Put** für jede Datei eine HEAD-Operation auf, um die Zeitstempel und MD5-Hashes jeder Ressource erneut abzurufen. Es ist zu erwarten, dass dieses Problem in einer zukünftigen Version dieses Pakets ohne Änderungen an der API behoben wird.

**•**
: Die Befehle **S3::Pull** und **S3::Push** rufen eine Verzeichnisauflistung ab, ohne **-max-count** zu verwenden. Das gesamte Verzeichnis wird auf einmal in den Arbeitsspeicher geladen. Bei sehr großen Buckets könnte dies zu einem Leistungsproblem führen. Der Autor hat derzeit nicht vor, dieses Verhalten zu ändern. Willkommen bei Open Source.

**•**
: **S3::Sync** wurde bislang weder konzipiert noch implementiert. Die Absicht besteht darin, Änderungen synchron zu halten, sodass Änderungen sowohl am Bucket als auch am lokalen Verzeichnis vorgenommen und anschließend durch **S3::Sync** zusammengeführt werden können.

**•**
: Auch **-compare** *calc* ist noch nicht vollständig implementiert. Dies liegt in erster Linie daran, dass Windows keine geeignete Methode zur Unterscheidung zwischen lokalen Dateien mit den Berechtigungen „public-read“ und „public-read-write“ bereitstellt. Unterstützung bei der Klärung der TWAPI-Spezifikationen in diesem Zusammenhang wäre willkommen. Auch die U\*\*X-Semantik lässt sich nur schwer direkt abbilden. Einzelheiten stehen im Quellcode. Hinweis: Es gibt keine Tests für calc, da diese Funktion noch nicht fertiggestellt ist.

**•**
: Die HTTP-Verarbeitung wird innerhalb der Bibliothek implementiert, anstatt ein „echtes“ HTTP-Paket zu verwenden. Daher werden mehrzeilige Header (noch) nicht korrekt verarbeitet. Fügen Sie keine Wagenrückläufe oder Zeilenvorschübe in x-amz-meta-\*-Header, Content-Type-Werte usw. ein. Der Autor geht derzeit nicht davon aus, dies zu verbessern.

**•**
: Intern sind **S3::Push**, **S3::Pull** und **S3::Toss** einander sehr ähnlich und sollten überarbeitet werden.

**•**
: Die Idee, mit **-compare** *never* und **-delete** *true* Dateien zu löschen, die an einer Stelle gelöscht wurden, an der anderen jedoch noch nicht, ohne dabei geänderte Dateien zu kopieren, ist noch nicht getestet worden.


# ANWENDUNGSEMPFEHLUNGEN

So rufen Sie ein „Verzeichnis“ aus einem Bucket ab, nehmen Änderungen vor und speichern es wieder zurück:

```
file mkdir ./tempfiles
S3::Pull -bucket sample -prefix of/interest -directory ./tempfiles \
  -timestamp aws
do_my_process ./tempfiles other arguments
S3::Push -bucket sample -prefix of/interest -directory ./tempfiles \
  -compare newer -delete true
```

Um Dateien lokal zu löschen, die aus S3 gelöscht wurden, ohne dabei sonstige Änderungen an den Dateien vorzunehmen:

```
S3::Pull -bucket sample -prefix of/interest -directory ./myfiles \
  -compare never -delete true
```

# ZUKÜNFTIGE ENTWICKLUNGEN

Der Autor beabsichtigt, neben der Fertigstellung der noch unvollständigen Funktionen an mehreren weiteren Projekten im Zusammenhang mit diesem Paket zu arbeiten.

Zunächst einmal ist ein Befehlszeilenprogramm nützlich, mit dem sich Buckets durchsuchen und Dateien aus Shell-Skripten und von der Befehlszeile übertragen lassen.

Zweitens wäre ein GUI-basiertes Programm nützlich, das eine visuelle Bearbeitung von Bucket- und Ressourcenbäumen ermöglicht, ähnlich wie der Windows Explorer.

Drittens ein Befehlszeilenprogramm (und möglicherweise auch ein GUI-basiertes Programm) namens „OddJob“, das S3 nutzt, um die Rechenaufgaben zwischen mehreren Servern, auf denen OddJob läuft, zu synchronisieren. Es wird ein S3-Bucket mit einer Reihe von auszuführenden Skripten eingerichtet, und das OddJob-Programm kann auf mehreren Rechnern aufgerufen werden, um die Skripte auf allen Rechnern auszuführen, wobei jeder Rechner nach Abschluss einer Aufgabe zur nächsten noch nicht gestarteten Aufgabe übergeht. Das Programm befindet sich noch in der Entwicklungsphase und ist in erster Linie für den Einsatz auf der Amazon Elastic Compute Cloud vorgesehen.

# TLS-SICHERHEITSHINWEISE

Dieses Paket nutzt das **TLS**-Paket, um die Sicherheit für **https**-URLs und andere Socket-Verbindungen zu gewährleisten.

Entscheidungen wie die Auswahl der zu unterstützenden Protokolle und der zu verwendenden Verschlüsselungsalgorithmen fallen jedoch weder in den Zuständigkeitsbereich von **TLS** noch in den des Pakets. Solche Entscheidungen liegen in der Verantwortung der jeweiligen Anwendung, die das Paket nutzt, und werden wahrscheinlich auch von den Servern beeinflusst, mit denen die Anwendung kommuniziert.

Angesichts des kürzlich von Google entdeckten [POODLE-Angriffs](http://googleonlinesecurity.blogspot.co.uk/2014/10/this-poodle-bites-exploiting-ssl-30.html) werden beispielsweise viele Server die Unterstützung für das SSLv3-Protokoll deaktivieren. Um dieser Änderung Rechnung zu tragen, müssen die Anwendungen, die **TLS** verwenden, gepatcht werden – nicht dieses Paket und auch nicht **TLS** selbst. Ein solcher Patch kann so einfach sein wie die allgemeine Aktivierung der **tls1**-Unterstützung, wie im folgenden Beispiel gezeigt.

```
    package require tls
    tls::init -tls1 1 ;# forcibly activate support for the TLS1 protocol

    ... your own application code ...
```

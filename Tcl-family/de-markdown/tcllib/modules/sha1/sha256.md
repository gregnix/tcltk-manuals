# Beschreibung

Dieses Paket enthält eine Implementierung der Message-Digest-Algorithmen SHA256 und SHA224 in Tcl gemäß der Spezifikation in FIPS PUB 180-1 (1). Diese Algorithmen nehmen eine Nachricht entgegen und erzeugen aus der Eingabe einen 256-Bit- (bzw. 224-Bit-)Digest. Die SHA2-Algorithmen sind mit dem SHA1-Algorithmus verwandt.

Dieses Paket bietet außerdem Unterstützung für die Erstellung verschlüsselter Nachrichten-Digests unter Verwendung des HMAC-Algorithmus aus RFC 2104 (3) mit SHA256 als Nachrichten-Digest.

*Achtung* Die Befehle in diesem Paket erwarten Binärdaten als Eingabe. Wenn ein **-file** angegeben wird, wird dies von den Befehlen selbst sichergestellt, da sie die referenzierte Datei im Binärmodus öffnen. Wenn stattdessen Literal-Daten oder ein **-channel** übergeben werden, ist der *Aufrufer des Befehls* dafür verantwortlich, dies sicherzustellen. Die erforderliche Kodierung des Konvertierungsbefehls lautet **encoding convertto utf-8 $string**.

*Achtung*, hier liegt ein *Tcl-9-Kompatibilitätsproblem* vor.

*Tcl 8.x behandelt* nicht-binäre Eingaben stillschweigend falsch, indem es diese intern auf die gewünschte Länge kürzt. Das heißt, indem nur das niedrige Byte eines höheren Unicode-Punkts verwendet wird. Es wird kein Fehler ausgelöst, das *Ergebnis ist einfach falsch*.

*Tcl 9 löst stattdessen einen Fehler aus*, d. h.

```
expected byte sequence but character <location> was ...
```

# Befehle

**::sha2::sha256** ?**-hex|-bin**? \[ **-channel channel** | **-file filename** | ?**--**? *string* \]
: Der Befehl nimmt eine Nachricht entgegen und gibt den SHA256-Digest dieser Nachricht als Hexadezimalzeichenfolge zurück. Sie können das Ergebnis als Binärdaten anfordern, indem Sie *-bin* angeben.

    Die zu hashenden Daten können entweder als Zeichenfolgenargument für den Befehl **sha256**, als Dateiname oder als bereits geöffneter Kanal angegeben werden. Wenn das Argument *-filename* angegeben wird, wird die Datei geöffnet, die Daten werden gelesen und gehasht und die Datei wird geschlossen. Wenn das Argument *-channel* angegeben wird, werden Daten aus dem Kanal bis zum Dateiende gelesen. Der Kanal wird nicht geschlossen. *Hinweis*: Die Verwendung der Kanal- oder Dateinamenoptionen führt zur internen Nutzung von **vwait**. Um verschachtelte Ereignisschleifen in Tk- oder tclhttpd-Anwendungen zu vermeiden, sollten Sie die inkrementelle Programmier-API verwenden (siehe unten).

    Es sollte nur eines der Argumente *-file*, *-channel* oder *string* angegeben werden.

    Wenn die zu hashende *string* mit einer Option verwechselt werden könnte (führender Bindestrich „-“), verwenden Sie davor die Option **--**, um den Prozess der Optionen-Verarbeitung zu beenden und die Interpretation als Zeichenkette zu erzwingen.

**::sha2::sha224** ?**-hex|-bin**? \[ **-channel channel** | **-file filename** | ?**--**? *string* \]
: Wie **::sha2::sha256**, nur dass hier der SHA224-Hash zurückgegeben wird.

**::sha2::hmac** *key* *string*
: siehe unten ...

**::sha2::hmac** ?**-hex|-bin**? **-key key** \[ **-channel channel** | **-file filename** | ?**--**? *string* \]
: Berechnet einen HMAC-Digest (Hashed Message Authentication Digest) unter Verwendung des SHA256-Digest-Algorithmus. HMACs sind in RFC 2104 (3) beschrieben und liefern einen SHA256-Digest, der einen Schlüssel enthält. Alle Optionen außer *-key* entsprechen denen des Befehls **::sha2::sha256**.

    Wenn die zu hashende *Zeichenkette* mit einer Option verwechselt werden könnte (führender Bindestrich „-“), setzen Sie die Option **--** davor, um den Options-Prozess zu beenden und die Interpretation als Zeichenkette zu erzwingen.


# Programmierschnittstelle

Für den Programmierer lässt sich der SHA256-Hash als eine Art „Behälter“ betrachten, in den Sie Daten einfüllen. Wenn Sie fertig sind, extrahieren Sie einen Wert, der aus den in den Behälter eingefüllten Daten abgeleitet wird. Die Programmierschnittstelle zum SHA256-Hash arbeitet mit einem Token (das dem Behälter entspricht). Sie rufen **SHA256Init** auf, um ein Token zu erhalten, und ruft anschließend so oft wie nötig **SHA256Update** auf, um Daten zum Hash hinzuzufügen. Um Ressourcen freizugeben und den Wert des Hashes zu erhalten, rufen Sie dann **SHA256Final** auf. Ein entsprechender Funktionssatz liefert Ihnen einen schlüsselgebundenen Digest (HMAC).

Wenn Sie **critcl** installiert und das **tcllibc**-Paket kompiliert haben, erfolgt die Implementierung der Hash-Funktion durch kompilierten Code. Andernfalls steht ein reines Tcl-Äquivalent zur Verfügung. Die Programmierschnittstelle bleibt in allen Fällen unverändert.

**::sha2::SHA256Init**
: siehe unten ...

**::sha2::SHA224Init**
: Erzeugt einen neuen SHA256/SHA224-Hash. Gibt eine Token-ID zurück, die für die verbleibenden Funktionen verwendet werden muss.

**::sha2::SHA256Update** *token* *data*
: Fügt Daten zu dem durch das Token identifizierten Hash hinzu. Der Aufruf von *SHA256Update $token „abcd“* entspricht dem Aufruf von *SHA256Update $token „ab“*, gefolgt von *SHA256Update $token „cb“*. Siehe [Beispiele]. Hinweis: Dieser Befehl wird sowohl für SHA256 als auch für SHA224 verwendet. Nur die Initialisierungs- und Abschlussbefehle der beiden Hash-Funktionen unterscheiden sich.

**::sha2::SHA256Final** *token*
: siehe unten ...

**::sha2::SHA224Final** *token*
: Gibt den Hash-Wert zurück und gibt alle von diesem Token belegten Ressourcen frei. Sobald dieser Befehl abgeschlossen ist, wird das Token ungültig. Das Ergebnis ist eine binäre Zeichenkette mit einer Länge von 32 bzw. 28 Byte, die den 256- bzw. 224-Bit-SHA256-/SHA224-Wert darstellt.

**::sha2::HMACInit** *key*
: Dies entspricht dem Befehl **::sha2::SHA256Init**, mit dem Unterschied, dass hierfür der Schlüssel angegeben werden muss, der in den HMAC einbezogen werden soll.

**::sha2::HMACUpdate** *token* *data*
: siehe unten ...

**::sha2::HMACFinal** *token*
: Diese Befehle entsprechen den entsprechenden SHA256-Befehlen.


# Beispiele

```
% sha2::sha256 "Tcl does SHA256"
0b91043ee484abd83c3e4b08d6034d71b937026379f0f59bda6e625e6e214789
```

```
% sha2::hmac Sekret "Tcl does SHA256"
4f9352c64d655e8a36abe73e6163a9d7a54039877c1c92ec90b07d48d4e854e0
```

```
% set tok [sha2::SHA256Init]
::sha2::1
% sha2::SHA256Update $tok "Tcl "
% sha2::SHA256Update $tok "does "
% sha2::SHA256Update $tok "SHA256"
% sha2::Hex [sha2::SHA256Final $tok]
0b91043ee484abd83c3e4b08d6034d71b937026379f0f59bda6e625e6e214789
```
